# Convex backend (`convex/`)

## Overview

The single backend for both apps: schema, queries, mutations, actions, crons, HTTP routes, and the Better Auth component. It lives at the repo root (not in a workspace) because the Convex CLI expects it there.

## Key files

| File | Owns |
|---|---|
| `schema.ts` | Domain tables and indexes — the source of truth for shape, no separate mirrored doc |
| `convex.config.ts` | Registered components (Better Auth, R2, push notifications) |
| `auth.ts`, `auth.config.ts`, `http.ts` | Better Auth integration and HTTP routes |
| `lib/authz.ts` | `getCurrentUser`, `requireUser`, role checks, audit helpers |
| `lib/recurrence.ts`, `lib/reminders.ts`, `lib/media.ts` | Shared domain helpers |
| `seed.ts`, `*Seed.ts` | Seed functions (`pnpm exec convex run seed:<name>`) |
| `*Migration.ts` | One off data migrations |
| `_generated/` | Generated by the CLI, never edit by hand |

## Commands

```bash
pnpm convex                               # dev deployment, watches and pushes changes
pnpm exec convex run seed:clans           # run one function
pnpm exec convex env set <KEY> "<value>"  # deployment env var
```

## Conventions

- Every mutation and sensitive query resolves the caller through `lib/authz.ts` and checks the role it needs. This is the real security boundary; admin middleware and layouts are only UX.
- Write an `activityLogs` row for every consequential state change.
- Enforce cardinality ("one Elder per clan") inside the mutation (revoke and replace, or reject), since Convex has no unique indexes.
- Import enums and validators from `@klt-cyber/shared`; never redefine them here.

## Gotchas

- Never write to the Better Auth component tables directly; link through `users.authId`.
- `convex/README.md` is the stock Convex template, not project documentation.
- A push to `main` deploys functions and schema to staging (`.github/workflows/deploy-staging.yml`), so schema changes must be backward compatible with live data or ship with a migration.
